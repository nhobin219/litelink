**This release moves every log's files.** A 0.1 log must be migrated before it can be
opened — `open` detects the old tree and names the command rather than reporting an absent
log:

```bash
python -m litelink.migrate --root ./data --name trades              # dry run
python -m litelink.migrate --root ./data --name trades --apply
```

Data files are neither moved nor rewritten; only pointers move. Pass `--archive s3://...`
to move the archive's metadata too. [Migrating from 0.1](https://github.com/nhobin219/litelink/blob/main/docs/RUNTIME.md#migrating-from-01)
covers multi-stream roots and retiring the old WAL replica.

Before 0.2, `catalog.db` and `archive.db` sat at the root shared by every stream, and
Iceberg metadata went to pyiceberg's default `<warehouse>/<namespace>/<table>` — so a
table's metadata lived at `<root>/litelink/<name>/metadata` while its data files were at
`<root>/<name>/data`, outside the location the table claimed and held together only by the
absolute paths in its manifests. Deleting a table's directory left every Parquet file
behind. Both tables now get an explicit location, everything a stream owns lives under
`<root>/<name>`, and the archive prefix mirrors it.

The sharing bought nothing — every query against those catalogs is keyed by
`(catalog, namespace, table)` and nothing ever read across streams — and it cost one
sidecar per root with a multi-stream config that had to be written by hand, `follow`'s
`root` parameter, and a blast radius of every stream under the root. It was not contention:
two streams sealing against one shared catalog measured 57.3 ms median against 66.1 ms for
separate roots.
